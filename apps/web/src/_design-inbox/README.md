# `_design-inbox/` — Claude Design landing zone

Verbatim Claude Design exports land here, one folder per route or feature:

```
_design-inbox/
  inbox/
    inbox.tsx          ← raw export
    notes.md           ← optional designer notes
    AUDIT.md           ← generated by scripts/design-component-audit.ts
    .scratch/          ← in-progress integration work; not promoted yet
  recipes/
    ...
```

**Nothing in this folder is imported by `App.tsx`.** Files here are source-of-truth design artifacts, kept under git for provenance. Integration moves a translated copy to `apps/web/src/pages/v2/` after audit.

## Workflow

1. Designer exports TSX from Claude Design (or hand-drops into the matching subfolder).
2. Run `bun run scripts/design-component-audit.ts <route>` to generate `AUDIT.md`.
3. Review `AUDIT.md`, accept/reject component substitutions and semantic-token swaps.
4. Apply mechanical changes inside `<route>/.scratch/` until the integrated page is ready.
5. Promote to `apps/web/src/pages/v2/<Route>.tsx`.
6. Add an Interceptor visual baseline to `tests/visual/<route>.baseline.png`.

See `docs/design/claude-design-handoff.md` for the full designer-facing guide.

## Convention notes

- One folder per route. Folder name uses the route path with `/` stripped: `inbox`, `recipes`, `research`, etc. Use kebab-case for multi-word routes.
- Filenames within a folder are the designer's choice; the audit script discovers `.tsx` files automatically.
- If a designer dumps a whole-app redesign, split it into per-route folders before running the audit pipeline.
- `.scratch/` is the only path safe to overwrite freely. Everything else outside `.scratch/` should be considered semi-permanent provenance.
