# v0.2 — Foundation Hardening

## Context

v0.1 shipped the spine of the system: HMAC-authenticated HTTP inbound → deterministic plan synthesis → `runtimed` execution over NDJSON IPC → reply with audit trail in SQLite. Commits `3ff4655` (frontend F1-F8 + backend Steps 4-6), `25728e5` (Step 7 scope cuts + HMAC auth), and `2a451e6` (Step 8 verification harness) close the v0.1 plan in full.

What v0.1 deliberately deferred:

- **No real connector is registered with the gateway.** The pump infra exists (`internal/connector/manager.go::RegisterSource`) and `smoke-e2e.sh` exercises it via a phantom `telegram-smoke` id, but no `connectors.Connector` instance lives inside the gateway process today. Step 8 Gate 3 covered the seam, not the prose.
- **No frontend route reads real backend data.** `lib/api.ts` has the `VITE_API_MODE_<ROUTE>=real` toggles, but no route flips them yet because no backend endpoint produces the right shape.
- **Workspace identity is a placeholder.** The HMAC token carries `tenant:user:role:channel:exp` only; `WorkspaceID` is stamped as the nil UUID in `handler.HandleInbound`. Multi-workspace deployments need this through claims.
- **Layer-4 policy is a stub.** `IRONGOLEM_LAYER4_ENABLED=true` returns "not implemented" — Step 7's fix made it auditable but didn't implement the channel-restrictions store.
- **No real-LLM smoke runs in CI.** The Anthropic provider is fully implemented in `runtime/runtimed/src/provider.rs` but only ever exercises the mock path because we don't ship an API key into CI.

v0.2 hardens these gaps without changing the v0.1 architecture. Same plan-then-build cadence as v0.1: each step is sized, dependency-graphed, and gated by an executable check before the next step starts.

## Confirmed Decisions

1. **No new top-level architecture.** The runtime↔gateway↔frontend layering stays as v0.1 shipped it. v0.2 fills in the seams, doesn't redraw them.
2. **Frontend↔backend integration goes one route at a time.** Inbox is first because the inbound flow is what v0.1 wired. Each integration is a single change in `apps/web/src/lib/api.ts` (flip the route's `getMock()` to `load()`) plus an Interceptor visual baseline.
3. **Telegram is the first real connector.** Other connectors graduate from `_deferred/` in v0.3+. v0.2 proves the connector adapter pattern with Telegram only.
4. **Layer-4 stays env-flagged until its store is real.** The Step 7 default-allow-with-loud-reason behavior survives until v0.2 Step 4 ships the actual store.
5. **Real-LLM smoke runs as an opt-in CI job.** Gate on an explicit `ANTHROPIC_API_KEY` GitHub secret. Mock path stays the default everywhere else.

## Sequenced Integration

### Step 1 — Real Telegram connector wire-up (M, no deps)

Finish what Step 8 Gate 3 mocked. After this step, sending a real Telegram update to the gateway lands in `HandleInbound` and the reply flows back through `connectors/telegram` `Send()`.

- **New**: `services/gateway/internal/connector/telegram_source.go` — adapter wrapping `connectors.Connector` as `InboundSource`. Translates `connectors.Message` ↔ gateway-local `InboundMessage` / `OutboundMessage`.
- **Modify**: `services/go.mod` — `replace github.com/Ph4wkm00n/IronGolem_OS/connectors => ../connectors` so the gateway can import the connectors module without restructuring it into the same Go module.
- **Modify**: `services/gateway/cmd/main.go` — at boot, if `IRONGOLEM_TELEGRAM_BOT_TOKEN` is set, instantiate the Telegram connector with `api_base` configurable via `IRONGOLEM_TELEGRAM_API_BASE` (defaults to `https://api.telegram.org`), and register it via `connMgr.RegisterSource("telegram", adapter)`.
- **Verification**: extend `smoke-e2e.sh` with a Go-based httptest variant (`scripts/smoke-telegram.sh` invoking a small Go binary at `services/gateway/cmd/smoke-telegram`) that stands up a fake Telegram API server, points the connector at it, sends a fake update, asserts both the gateway reply path AND the `sendMessage` POST landed on the impersonator with the right `chat_id` + `text=pong`.

### Step 2 — Workspace identity through token claims (S, no deps, parallel with Step 1)

`WorkspaceID` is currently the nil UUID. Plumb it through HMAC token claims so multi-workspace deployments work.

- **Modify**: `services/gateway/internal/middleware/auth.go` — extend `TokenClaims` with `WorkspaceID string`. Wire format becomes `<tenant>:<workspace>:<user>:<role>:<channel>:<exp>.<mac>` (5 → 6 fields). The MAC covers the new payload shape, so old tokens fail verify — there's no compat layer because v0.1 never minted long-lived tokens.
- **Modify**: `tenant.go` — add `WorkspaceIDFromContext`. `HandleInbound` reads it instead of stamping nil-UUID.
- **Modify**: `cmd/mint-token/main.go` — add `--workspace` flag. Defaults to the nil-UUID string so existing scripts still produce valid tokens for solo mode.
- **Verification**: extend `auth_test.go` and `chain_test.go` with `WorkspaceID` round-trip + token-version rejection (old 5-field tokens must 401).

### Step 3 — F6 Inbox real-API (M, depends on Steps 1-2)

First live frontend↔backend integration. After this step, the v2 Inbox renders rows derived from real audit events rather than the inline mock.

- **New**: `services/gateway/internal/handler/inbox.go` — `GET /api/v1/inbox` that lists `message.inbound` events for the authenticated tenant + workspace, shaped to match `apps/web/src/_mocks/inbox.ts::Item`. Status/risk/source mapping is deterministic from event payload metadata.
- **Modify**: `apps/web/src/lib/api.ts` — `v2.inbox.list()` flips behavior when `VITE_API_MODE_INBOX=real`. Pages remain sync (`getMock()`) by default; opt-in async via the env flag.
- **Modify**: `apps/web/src/pages/v2/Inbox.tsx` — small `useEffect` + `useState` shim that calls `api.v2.inbox.list()` and replaces `initialItems` when in real mode.
- **Verification**: new Go integration test that boots the gateway, fires N inbound messages via `HandleInbound`, calls `/api/v1/inbox`, asserts the response matches the wire shape. Interceptor visual baseline regenerated against `VITE_API_MODE_INBOX=real` once the smoke gateway runs alongside `vite preview`.

### Step 4 — Layer-4 channel policy store (M, no deps, parallel with Steps 1-3)

The Step 7 stub-as-allow fix bought us auditability. v0.2 makes the layer actually enforce.

- **Modify**: `services/pkg/policy/policy.go` — `perChannelRestrictionChecker` gains a `store ChannelPolicyStore` field. Default impl checks each channel against the store's allow/deny rules; falls back to the v0.1 disabled-with-reason behavior when the store is empty.
- **New**: `services/gateway/internal/policy/store.go` — SQLite-backed `ChannelPolicyStore` (same `*sql.DB` the four handler stores share). Schema: `channel_policies(channel_id, action, decision, reason, created_at)`.
- **Modify**: `gateway/cmd/main.go` — construct + inject the store when wiring the policy engine.
- **Verification**: new tests in `pkg/policy` covering deny-by-rule, allow-by-rule, and missing-rule fallback. Migration runs through `persist.Migrate`.

### Step 5 — Real-LLM CI smoke (S, depends on Step 1)

Validate the Anthropic provider end-to-end without breaking the default mock path.

- **New**: `.github/workflows/llm-smoke.yml` — manual-dispatch + nightly cron job. Pulls `ANTHROPIC_API_KEY` from repo secrets, sets `IRONGOLEM_LLM_PROVIDER=anthropic`, runs a single-prompt smoke against the deployed `runtimed` binary inside the gateway, asserts the reply is non-empty and non-mock.
- **New**: `scripts/smoke-llm.sh` — reusable harness invoked by the workflow.
- **Verification**: workflow run goes green when triggered manually; cron failures alert via existing CI notification.

### Step 6 — Home + Health F6 wiring (S, depends on Step 3 pattern)

Now that Inbox has the contract template, apply it to the two routes whose backend signals already exist.

- **Modify**: `apps/web/src/pages/v2/Home.tsx` — flip `VITE_API_MODE_HOME=real`. Derives heartbeat + initial-events from `/api/v1/health/status` + `/api/v1/events?kind=*` (already exists in v0.1).
- **Modify**: `apps/web/src/pages/v2/Health.tsx` — same shape, against `/api/v1/health/status` once we add component-level reporting.
- **Verification**: visual baseline regen for both routes.

### Step 7 — Release polish (S, depends on all prior)

- Regenerate every visual baseline against the real production Vite build (`scripts/visual-capture.sh`).
- Write `CHANGELOG.md` covering v0.1 + v0.2.
- Tag `v0.2.0` once `make test-visual` and `make smoke-e2e` both stay green on `main`.

## How This Composes With the v0.1 Surface

```
v0.1 (shipped)                              v0.2 (this plan)
─────────────────────                        ──────────────────────────
HMAC token (5-field claims)            →    HMAC token (6-field claims, WorkspaceID)
HandleInbound stamps nil workspace_id  →    HandleInbound reads from claims
Connector pump (no source)             →    Telegram source registered (Step 1)
Layer 4 stub-allow with reason         →    Layer 4 enforces from store (Step 4)
v2 routes on mocks                     →    Inbox/Home/Health on real backend (Steps 3, 6)

```

## Out of Scope (v0.2)

- gRPC migration for the runtime IPC. Stays NDJSON until v0.3 fleet mode lands.
- mTLS replacing HMAC tokens. Stays HMAC until v0.3.
- Graduating deferred services from `_deferred/`. Each comes back when its behavior is actually consumed by the gateway runtime — not before.
- Recipe / Approval / Squad real-API for the v2 frontend. Those routes remain on mocks; v0.3 wires them once their backend semantics solidify.
- Multi-tool registry beyond `echo` / `http_get`. The sandbox registry stays as v0.1 shipped it.

## Risk Register

| ID | Risk | Resolution |
|---|---|---|
| R1 | Cross-module dep (services → connectors) breaks CI | Use `replace` directive in `services/go.mod`. CI already builds connectors module separately; both still satisfied. |
| R2 | Token shape change breaks in-flight tokens | Acceptable — v0.1 has no long-lived tokens. Tag the change loudly in the PR + CHANGELOG. |
| R3 | Inbox listing reshapes audit-event data into Item type, leaking implementation details | Keep the mapping inside `handler/inbox.go`; the audit event is still the source of truth. Document the mapping in the file header. |
| R4 | Layer-4 store ships with empty rules, behavior changes silently when first rule added | Tests cover the empty-store fallback path; document in `policy.go` that store-empty == disabled. |
| R5 | Real-LLM smoke costs $ per nightly run | Set `max_tokens: 64`, fixed prompt. Estimated <$0.01/run at current Anthropic pricing. |

## Migration Path Notes (forward)

- **Token claims**: v0.2 → v0.3 may add `expires_refresh_at` for sliding renewal. Token format stays dot-delimited; consumers parse by field count.
- **Channel policy store**: schema starts allow-list-only in v0.2. v0.3 adds rate-limit fields per `(channel, action)` pair. Same table, additive columns.
- **Connector adapter pattern**: the `telegram_source.go` shape generalizes. v0.3 graduates more connectors from `_deferred/` by copying this file and pointing at the matching `connectors/<name>/`.

## Open Questions

These don't block starting v0.2 but sharpen specific steps.

1. **Inbox listing pagination shape** — match the v0.1 `/api/v1/events` page+pageSize convention, or move to cursor-based pagination? Decision point at the start of Step 3.
2. **Workspace claim semantics in solo mode** — empty string in claim = nil-UUID workspace, or require an explicit workspace token? Pick at the start of Step 2.
3. **Anthropic model selection in smoke** — pin a model name in `IRONGOLEM_LLM_MODEL` or let the runtime default win? Cost / signal tradeoff at Step 5.
